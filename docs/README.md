# ALPHASE 대회 설계·구현 기준

**현재 변경 기준은 [v4 설계·구현 업그레이드](UPGRADE_V4.md)** 다. O/L/S 독립 후보, train-only morphology, self-contained resume, 엄격한 평가 출처/seed/budget gate가 v3에 추가되었다. 아래는 v3 배경과 탐색 문서다.

기준일: 2026-10-11 KST. 대상: `E:\Competition\코맵`. 사용자 요청에 따라 설계 전용에서 **코드 구현·로컬 검증 포함**으로 범위를 확장했다. GPU 임대·유료 지출·대회 제출은 하지 않았다.

## 현재 결론

주력은 **EfficientNet-B3 + U-Net++**, 도전 후보는 **ConvNeXt-Tiny + U-Net**이다. 70장 소량 데이터에서 상·경계 보존, 큰 문맥, 재현 가능한 모델 선택에 투자한다. 단일 모델과 최대 3개 가중치의 확률 앙상블 중 실제 검증을 통과한 것을 제출한다. `champion.json`이라는 파일명은 설계상 주력이라는 뜻이며 이미 최고 성능을 측정했다는 뜻이 아니다.

실제 데이터 검사, CPU 단위·통합 테스트 및 실제 train crop의 수치 검사는 완료했다. **GPU 512 학습, 사전학습 가중치 학습, 최종 mIoU, 예산 소요는 미측정**이다. 합성 테스트 점수를 대회 성능으로 사용하지 않는다.

## 읽는 순서

실행 담당자는 먼저 [단계별 행동 지침](ACTION_GUIDE.md)을 읽고 [체크리스트](EXECUTION_CHECKLIST.md)에서 현재 단계를 확인한다. [기록 양식](EXECUTION_RECORD_TEMPLATE.md)에 승인·규정·비용·실험·최종 산출물을 남기며, 중단·실패는 [복구 지침](RECOVERY_GUIDE.md)으로 처리한다. G0/G1 이전 확인을 마치지 않고 유료 작업으로 건너뛰지 않는다.

1. [경쟁 전략·모델 설계](MODEL_DESIGN.md): 모델, 손실, 증강, 선택 기준, 버린 선택지.
2. [데이터·평가·제출 계약](DATA_AND_EVALUATION.md): 실물 확인, 공식 규칙과 미결 사항.
3. [실행·실험·예산](RUNBOOK.md): 안전한 실행 순서, seed, 중단 기준, 비용 산식.
4. [폴더·파일 지도](FILE_MAP.md): 모든 직접 관리 파일의 역할 및 상세 모듈 문서.
5. [검증 기록](VERIFICATION.md): 수행한 검증과 남은 GPU·규정 게이트.

이 문서 묶음이 과거 Notion F1–F12 및 README v0.2의 상충하는 계획보다 우선한다. 기존 데이터와 압축 파일은 보존한다. v2/v3 체크포인트는 추론 호환만 유지하고 v0.4 학습 재개에는 사용하지 않는다.

## 상태를 구분하는 규칙

- 구현됨: 코드와 로컬 회귀 테스트가 존재한다.
- 수치 검증됨: 실제 입력에서 shape·finite loss/gradient 등 동작을 검사했다.
- 성능 입증됨: 정해진 protocol·seed에서 검증 점수를 실제 측정했다. **현재 해당 없음.**
- 규정 확인 필요: 외부 사전학습, union=0 처리, 출력 규격, 실행 파일의 인정 범위.

## 원칙

- test 정답·외부 유사 정답 수집, test 기반 모델 선택·pseudo-label 학습을 하지 않는다.
- 70/20 공식 분할을 보존한다. validation은 모델 선택에만 사용하며 train 증강·샘플러 통계에 들어가지 않는다.
- 단위 테스트 PASS는 우승 또는 GPU 호환의 증거가 아니다.
- 마감 전에는 유효 제출과 재현성이 신규 모델 추가보다 우선한다.
